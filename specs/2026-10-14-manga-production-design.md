# 만화 제작 보조 설계 (E)

작성일: 2026-10-14

## 배경

E는 로드맵에서 "만화 제작 보조"로 불렸고, 브레인스토밍 시점에 구체적 기능이
정해지지 않았다. 이 문서는 **무엇을 만들지 정하기 전에 무엇이 이미 있는지**를
먼저 조사한 결과에서 출발한다 — 그 결과가 범위를 크게 바꾸었다.

### 이미 있는 것 (조사 결과)

**파이프라인이 말풍선과 패널을 이미 검출하고, 그 결과를 이미 다각형으로 저장한다.**
`koharu-pipeline`의 검출 단계가 세 라벨을 만들고(`crates/koharu-pipeline/src/stages/detection.rs`의
`region_kind`):

| 라벨 | `RegionKind` | 정의 |
|---|---|---|
| `text` | `TextRegion::KIND` | `semantics.rs:13` |
| `bubble` | `BubbleRegion::KIND` | `semantics.rs:18` |
| `panel` | `PanelRegion::KIND` | `semantics.rs:23` |

**핵심**: 말풍선 검출은 마스크를 **다각형으로 근사해 `Geometry`로 저장**한다.
`mask_geometry`(`detection.rs:1325-1348`)가 마스크의 윤곽선을 찾고
`approximate_polygon_dp`(Douglas-Peucker)로 단순화해 `Geometry { origin, points }`를
만든다. 실패하면 바운딩 박스 사각형으로 폴백한다(`detection.rs:151-152`).

**`Geometry`는 C가 선택 영역에 쓰는 바로 그 다각형 타입이다**
(`spatial.rs:21-24`). 즉:

- "말풍선을 찾는" 기능은 **이미 있다** — E의 범위가 아니다.
- "마스크를 다각형으로 바꾸는" 기능도 **이미 있다** — E가 할 필요가 없다.
- 검출 영역은 이미 `Geometry`이므로 **C의 `SelectionShape::Lasso { points }`로
  그대로 옮길 수 있다.** 변환이 자명하다.

또한 `koharu-ml`·`koharu-diffusion`·`koharu-llama`·`koharu-translator`가 있어
인페인팅·번역·생성이 이미 파이프라인에 있다.

**그러므로 E1은 "검출 영역을 선택으로 복사하는 것" 한 줄에 가깝다.**

### 검출 엔티티의 수명 (조사 결과)

검출은 **매 실행마다 엔티티를 새로 만든다.** `run`이 기존 것을
`remove_entity(entity, RemovePolicy::Cascade)`로 지우고(`detection.rs:252`)
`add_entity(page, At::End)`로 다시 만든다(`detection.rs:343`).

**그러므로 검출 엔티티 ID는 재실행 사이에 안정적이지 않다.** 검출을 다시 돌리면
같은 말풍선이 **다른 ID**를 갖는다.

**이 사실이 E의 설계를 정한다**: 선택이 검출 엔티티를 **참조하면 안 된다.**
참조하면 재검출 후 선택이 다른 영역을 가리키거나 무효가 된다. 대신 선택은
**검출 시점의 `Geometry`를 복사**한다 — 좌표 값이므로 재검출과 무관하게 살아 있다.

이것은 E-D1을 "마스크 참조"가 아니라 **"다각형 복사"**로 확정한다.

### 그래서 E는 무엇인가

E를 **"이미 검출된 다각형을 편집 도구에 연결하고, 만화 제작 프리셋을 얹는 것"**으로
정의한다:

| 덩어리 | 내용 | 근거 |
|---|---|---|
| E1 | 검출 영역 → **선택 영역으로 복사** | 검출 영역이 이미 `Geometry`이고 C의 선택이 다각형이다. 참조가 아니라 복사다(위 수명 조사) |
| E2 | **스크린톤/톤 붙이기** — 선택 영역이나 도형 안에 망점·선 패턴을 채운다 | 1c의 패턴 위에 얹힌다. 만화 제작의 핵심 반복 작업이다 |
| E3 | **말풍선 도구** — 말풍선 도형을 만들고 텍스트를 넣는다 | 도형(1a) + 패턴(1c) + 텍스트(기존)를 조합한 것 |

**E1이 먼저다.** E2·E3은 E1이 만든 "검출 → 선택" 경로를 쓰고, E1은 기존 데이터를
읽기만 하므로 새 저장 스키마가 없다.

## 범위

**포함**: 검출 영역 → 선택 변환, 톤 채우기, 말풍선 도구.
**제외**: 말풍선 검출(이미 있음), 텍스트 인식·번역(이미 있음), 인페인팅(이미 있음),
스크린톤 자동 배치(어떤 영역에 어떤 톤을 쓸지는 창작 결정이다).

## 결정 사항

| # | 결정 | 근거 |
|---|---|---|
| E-D1 | 검출 영역 → 선택 변환은 **`Geometry`의 점을 복사**한다. 참조도, 마스크도 아니다 | 검출 영역은 이미 `Geometry`(다각형)이고(`detection.rs:1325-1348`), C의 선택도 다각형이다. **참조하면 안 되는 이유는 검출 엔티티 ID가 재실행 사이에 안정적이지 않기 때문이다** — 검출은 기존 것을 `Cascade`로 지우고 새로 만든다(`detection.rs:252`, `:343`) |
| E-D2 | 마스크 근사를 **E가 하지 않는다** | 이미 되어 있다. `mask_geometry`가 Douglas-Peucker로 근사해 `Geometry`로 저장한다. E가 다시 하면 두 근사가 생겨 두 권위가 된다 |
| E-D3 | 톤 채우기는 **패턴 위에 정의**된다. 새 채우기 종류를 만들지 않는다 | 1c가 `ShapeFill::Pattern`과 `PatternSpec`을 만든다. 톤은 "주기·각도·점 크기가 있는 패턴"일 뿐이므로, 톤을 위한 별도 채우기 종류는 중복이다. **톤은 `PatternSpec`의 프리셋 + 생성기**다 |
| E-D4 | 톤 생성기는 **망점(dot)과 선(line) 두 종류** | 만화 톤의 대부분이다. 그라데이션 톤은 패턴의 `scale`·`rotate`로 흉내낼 수 있다 |
| E-D5 | 톤은 **래스터화해서 저장하지 않고** `PatternSpec`으로 저장한다 | 래스터화하면 해상도에 종속되고 편집할 수 없다. 1a가 도형을 벡터로 저장하고 래스터화를 내보내기 시점으로 미룬 것과 같은 원칙이다 |
| E-D6 | 말풍선은 **도형의 한 종류**가 아니라 **도형 + 텍스트의 그룹**이다 | 말풍선은 "타원 하나"가 아니라 꼬리·테두리·안쪽 텍스트의 조합이다. 도형 종류로 만들면 그 조합을 도형 종류마다 다시 구현해야 한다. 그룹으로 만들면 기존 도형·텍스트·패턴을 조합한다 |
| E-D7 | 말풍선 도구는 **그룹 생성 프리셋**이다 — 클릭하면 "타원 도형 + 텍스트 레이어" 그룹을 만든다 | E-D6의 직접적 결과다. 새 컴포넌트가 없고 그룹 생성 커맨드 하나면 된다 |

### E-D1이 가장 중요한 결정이다

C의 S-D1은 선택을 다각형으로 정하면서 이유를 들었다: 마스크는 히스토리에 큰
버퍼를 넣고, 마스크와 다각형이 둘 다 있으면 두 권위가 된다.

조사 결과 **검출 영역은 이미 다각형이다.** 그러므로 E는 그 결정과 충돌하지 않고
오히려 그것을 쓴다 — 검출 영역의 점을 복사해 C의 올가미 선택으로 만들면 된다.

**참조가 아니라 복사인 이유**는 검출 엔티티의 수명이다. 검출을 재실행하면 기존
엔티티가 `Cascade`로 삭제되고 새로 만들어지므로(`detection.rs:252`, `:343`) ID가
바뀐다. 선택이 ID를 참조하면:

- 재검출 후 선택이 **다른 영역**을 가리키거나 (ID 재사용 시)
- 무효가 된다 (ID가 사라질 때)

둘 다 사용자에게 설명할 수 없는 동작이다. **좌표를 복사하면 재검출과 무관하게
선택이 안정적이다** — 사용자가 "이 말풍선"을 골랐다면 그 순간의 모양이 선택이다.

**대가**: 검출을 다시 돌려 말풍선 모양이 바뀌어도 이미 만든 선택은 예전 모양이다.
이는 올바른 동작이다 — 선택은 사용자가 고른 시점의 영역이고, 사용자가 다시
고르면 갱신된다.

### 저장 모델

**E1은 새 저장 스키마가 없다.** 검출 결과는 `DetectionAnalysis`와 `Geometry`로
이미 저장된다(`detection.rs:356-403`). 선택은 C의 `SelectionShape::Lasso`이므로
새 변형조차 필요 없다 — **E1은 순수 조회 + 복사**다.

**E3은 새 컴포넌트가 없다.** 그룹 생성이므로 기존 `groups.rs`의 그룹을 쓴다.

**E2의 톤**은 1c의 `PatternSpec`을 쓰되 **생성기 정보**를 함께 저장해야 한다.
패턴 자산은 픽셀이고, 톤의 "주기 4px, 각도 45도, 점 크기 1px"는 그 픽셀을 만든
파라미터다. 이것을 저장하지 않으면 톤을 편집할 수 없다.

**여기서 P-D2(패턴은 도형 레이어가 소유)와 충돌할 수 있다.** 톤을 파라미터로
저장하려면 자산이 아니라 파라미터가 권위여야 한다. 해결:

```rust
pub enum ShapeFill {
    Solid([u8; 4]),
    Gradient(GradientSpec),
    Pattern(PatternSpec),
    Tone(ToneSpec),              // E가 추가
}

pub struct ToneSpec {
    /// 톤 종류와 파라미터. 자산이 아니라 이 값이 권위다.
    pub pattern: TonePattern,
    /// 위 패턴을 1c의 타일러로 어떻게 반복할지.
    pub spec: PatternSpec,
}

pub enum TonePattern {
    /// 망점: 격자 위의 원. 간격·반지름은 프레임 로컬 정규화 값.
    Dots { spacing: f32, radius: f32 },
    /// 선: 일정 간격의 평행선.
    Lines { spacing: f32, width: f32 },
}
```

**`ToneSpec`은 자산을 참조하지 않는다.** 렌더러가 파라미터에서 픽셀을 만든다.
그러므로 P-D2의 "패턴은 도형 레이어가 소유" 규칙이 깨지지 않는다 — 톤은 자산이
아예 없��. `PatternSpec`은 "어떻게 반복할지"만 담당하므로 두 변형이 공유할 수 있다.

## 커맨드

### E1 — 검출 영역 선택

```rust
pub async fn detected_region_selection(
    page: EntityId,
    region: EntityId,
) -> Result<SelectionShape, Error>
```

**픽셀을 바꾸지 않으므로 커밋이 아니다.** 선택을 만들 뿐이고 선택은 저장되지
않는다(S-D2). 그러므로 이것은 **조회**이며, 검출 엔티티의 `Geometry`를 읽어
`SelectionShape::Lasso { points }`로 복사해 돌려준다.

**`SelectionShape`에 새 변형이 필요 없다.** 검출 영역이 이미 `Geometry`이므로
C의 `Lasso`가 그대로 맞는다. 이는 E-D1·E-D2를 정확히 반영한다 — 변환도 참조도
아니라 **점 복사**다.

`Geometry`는 `origin`(Origin::User 등)을 함께 갖지만 선택은 좌표만 쓰므로
**점만 복사하고 `origin`은 무시한다.** 이 결정을 주석에 남긴다 — 검출 기하가
`Origin::Model`일 수 있고, 선택은 출처와 무관하게 좌표로 판정한다.

검출 엔티티가 검출 영역이 아니면(예: 텍스트 레이어) 거부한다. 판정은
`DetectionAnalysis` 컴포넌트의 존재로 한다(`analysis.rs:138-147`).

### E2 — 톤

```rust
pub async fn set_shape_tone(
    expected_revision: Revision,
    layer: EntityId,
    tone: Option<ToneSpec>,
) -> Result<LayerCommit, Error>
```

`None`이면 `Solid`로 되돌린다. 1c의 `set_shape_pattern`과 같은 형태다.

### E3 — 말풍선

```rust
pub async fn create_balloon(
    expected_revision: Revision,
    page: EntityId,
    frame: Frame,
    at: At,
) -> Result<LayerCommit, Error>
```

`Frame`(1a의 도형 프레임) 위치에 그룹을 만들고, **자식으로 타원 도형과 텍스트
레이어를 넣는다.** 자식의 초기 스타일은 고정 프리셋이고, 이후에는 사용자가
각각을 편집한다 — 말풍선 그룹은 특별한 컴포넌트가 아니라 평범한 그룹이다.

## 실패 시나리오

| 상황 | 처리 |
|---|---|
| 검출 결과가 없는 페이지에서 영역 선택 | 선택 없음. 오류가 아니다 |
| 검출 엔티티가 삭제됨(재검출) | **아무 일도 없다.** 선택은 좌표를 복사했으므로 검출과 독립이다(E-D1). 재검출이 선택을 무효화하지 않는다 |
| 톤의 `spacing`이 0 | 거부 (무한 반복) |
| 톤의 `radius`가 `spacing`보다 큼 | 허용하되 원이 겹친다. 거부하지 않는다 — 겹친 톤은 유효한 표현이다 |
| `create_balloon`의 프레임이 페이지 밖 | 허용(D의 D-D2와 같은 원칙 — 페이지 밖 내용은 남아 있다) |
| `create_balloon`이 부분 실패 | 하나의 `Edit`이므로 원자적이다. 중간 상태가 커밋되지 않는다 |

## 다른 서브프로젝트와의 관계

- **C를 확장한다.** C가 `SelectionShape`를 만들고, E가 변형 하나를 추가한다.
  **C를 먼저 구현해야 한다.**
- **1c를 쓴다.** `PatternSpec`과 타일러를 재사용한다. **1c를 먼저 구현해야 한다.**
- **D3을 쓴다.** 말풍선에 이미지를 넣는 것은 D3의 삽입 경로다.
- **B·D와 독립적이다.**

**구현 순서**: E1 → E2 → E3. E1은 C만 필요하고, E2는 1c와 B3을 필요로 하며,
E3은 셋 다 필요로 한다.

## 열린 문제

1. **~~검출 영역 ID가 안정적인가~~** — **해결됨.** 검출은 매 실행마다 엔티티를
   `Cascade`로 지우고 새로 만든다(`detection.rs:252`, `:343`). **ID는 안정적이지
   않다.** 그러므로 E-D1은 참조가 아니라 **점 복사**로 확정되었다. 이 조사가
   설계를 바꾼 지점이므로 여기 남긴다.
2. **톤의 좌표계.** `TonePattern`의 `spacing`·`radius`를 프레임 로컬 정규화로
   두면 페이지 크기가 바뀔 때 톤의 물리적 크기가 바뀐다. 1c의 `scale`과 같은
   결정이므로 **1c와 일관되게 정한다** (1c의 열린 문제 1과 같은 답).
3. **말풍선 프리셋의 내용.** 타원 크기 대비 텍스트 여백, 기본 폰트 크기, 꼬리
   유무. 1차는 꼬리 없이(타원 + 텍스트) 시작하고, 꼬리는 사용자가 도형으로
   그린다. **계획에서 확정한다.**
4. **~~`Geometry`의 `origin` 처리~~** — **해결됨.** `mask_geometry`는
   `Origin::User`를 돌려주고 점에 이미 마스크 원점을 더해 저장한다
   (`detection.rs:1345-1356` — `x: point.x - 1 + origin.0`). 즉 **점이 이미 페이지
   좌표다.** 그러므로 E-D1이 `origin`을 무시하고 점만 복사하는 것이 옳다.
   `Origin::Generated`는 `DetectionAnalysis`·`Region` 컴포넌트에 붙고
   기하에는 붙지 않는다(`detection.rs:361`, `:370`).
